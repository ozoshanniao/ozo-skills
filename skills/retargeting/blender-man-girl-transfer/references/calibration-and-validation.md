# 校准方法与已验证边界

## 为什么不能直接共享 Action

历史检查两套骨架各 423 骨，手臂局部 Y 接近同向、X/Z 接近反向，上臂静止基约差 157°、前臂/手约 160°，并非精确 180°。它们还有 `Torso/Troso`、手指和 Tweak 名称及父级差异。四元数动画不能简单某轴乘以 -1；修改目标 Bone Roll 会影响现有绑定与动作。

核心对每对控制骨取 `C = inverse(target_rest_rotation) @ source_rest_rotation`，候选局部旋转为 `C @ source_basis_rotation @ inverse(C)`，位移按 `C` 换基；保留允许的缩放和属性。父级不同的控制器（如 Shoe_Tip）还需依据完整求值朝向补偿；只换局部基不够。

`ROOT/ROOT_Sec` 原有变换曲线保留关键帧、手柄和插值；未关键帧分量也显式写入。数值自定义属性的关键帧曲线按映射复制，未关键帧值写明确常量。源专有 `ROOT/根运动Y` 是已知源 UI 标记，报告后跳过，不能扩展成任意属性忽略规则。

## Clap 前臂修复的关键发现

早期 9.27° 指标混入了不同静止 A-pose 的参考差异。源 Tweak 绕肢体 Y 扭转约 40°，完整静止基共轭后轴向偏斜，Stretch To 又将结果骨朝向摆回肘腕连线。不能仅靠提高采样密度处理。

修复使用 `arm_twist.py`：在源 FK 与结果骨之间取相对运动，结合各自静止 FK/结果骨关系及沿肢体轴平行运输后的 Roll，构造目标朝向。候选 FK 保留目标自然肩肘腕方向，只拟合需要的扭转。

针对双侧上臂/前臂主 Tweak 和 01/02 分段 Tweak，共 12 个控制器：先主骨后分段，测量本地 Y 微扰后的实际结果骨响应，以有限次标量迭代拟合。响应异常会停止；不改绑定、Pole Angle 或骨轴。四元数沿时间保持同号连续。

验收仍比较依赖图最终结果，不以控制器输入值小误差代替形变正确，也不通过放宽阈值让动作过关。

## 自动骨架验收覆盖

| 指标 | 当前校准阈值/要求 |
| --- | --- |
| 主要结果骨参考旋转 | 最大 3° |
| 控制器旋转、手臂相对 FK 参考旋转 | 最大 0.15° |
| 控制器换基后位置 | 最大 0.00025 场景单位 |
| 控制器缩放 | 最大 0.0001 |
| 原生属性误差 | 最大 0.000001 |
| 根骨姿态矩阵分量 | 最大 0.00002 |
| 双侧膝平面 | 有效采样下点积必须大于 0 |
| 腿部拉伸 | 最多静止长的 1.05 倍 |

本机历史场景以米为尺度，但不能把数值自动称作米；读取单位后解释。验证默认覆盖不大于 0.25 帧间隔，并包含原关键帧。有限采样不代表证明所有连续时刻。

腿/胫及分段辅助骨受目标肢长与扭转分配影响，不用相同静止增量作为统一姿态阈值。报告 `dependent_rotation_max_deg` 和逐骨最差帧，同时检查膝平面、拉伸与视觉形变；它们不受“主要结果骨 3°”统一约束，不能隐藏为全骨骼均小于 3°。

自动报告不包含完整网格、穿插深度、鞋底接地、物体接触、循环接缝等验收。掌面工具依据顶点组权重提取表面；拓扑或权重变化时先核对选区。最近距离与相交三角面对数都不等于完整穿插深度。

## 历史结果，仅作回归依据

- ThumbUp：1–62 帧、245 个 0.25 帧采样，主要结果骨最大约 0.82°；合成测试验证根平移/旋转、失败回退、模式拒绝及漏映射拒绝。
- Clap：1–61 帧、每帧烘焙、241 个采样，修复后手臂相对参考最大约 0.00409°，主要结果骨最大约 0.37952°（脚趾），根矩阵误差 0；腿部依赖指标仍有更大差异。168 个分组=164 控制器＋4 机制骨属性组，并非所有动作固定 168 组。
- Clap 六次拍手节奏保留。原动画已有掌面相交；目标也有轻微相交，本次未做接触重创作。历史最近距离约 0.02–3.94 mm 不是新动作验收标准。
- 没有指定地面几何；历史最低 Z 约 -3.42 mm 只能诊断，未进行实际地面接触验收。
- 当时正式新动作为 `03-Girl-Clap_Repaired`，原 Action 与源保持，场景未保存。它们不是未来运行时的固定 Action/文件名。
