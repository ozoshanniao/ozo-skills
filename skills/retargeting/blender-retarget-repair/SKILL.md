# Blender 动画重定向与修复

## 用户约定与分工

- 使用 MCP 读取当前 Blender 场景。多个 Blender 窗口时，先列出可识别的窗口、文件路径与进程，询问用户选哪个，再连接所选实例。不能默认选前台、最新文件或默认端口。
- 对新动画，先分析动画，再分析并填写骨骼映射；Remap 与 Retarget 都包含映射检查。相同骨架的配置可以验证后复用，无需每次重建列表。
- 映射准备好后，由用户手动调整参考姿态、Apply 并点击正式重定向。Codex 提供参数与检查点，等待用户告知完成，不自行代替用户点击正式重定向。
- 每个新动画提前确认根运动要求：保留源位移、转移到指定根控制器（如 ROOT_Sec）、原地化，或其他方案；明确处理哪些平移/旋转轴。已有明确指示沿用，不重复询问。未确认时可继续读取、分析和普通映射检查，暂不提交依赖该决定的 Root 设置和修复。
- 用户请求“检查/分析”时只检查；请求填写映射或开始新重定向流程时可完成相应配置；请求修复时才修改动画。轻微局部偏差默认报告给用户手修；严重系统误差说明修复范围，获得本次修复授权后执行。用户已说“帮我修”即为该范围的授权。
- 可以用隔离副本测试。最终结果回到用户所选的当前 Blender 文件内，创建独立的新 Action，在同一骨架上切换对比，保留原 Action。用户所说的“新 Action 插槽”指独立 Action，不是同一个 Action 内新增 Slot。测试 .blend 不作为最终交付。
- 用户最新手调、增量修正后的状态是基线。写入前重新读取，不能拿旧副本覆盖后来调整。

## 按需读取参考

- 连接不明确、MCP 掉线或建立基线时，读 [连接与场景读取](references/connection-and-baseline.md)。
- 处理问题或准备修复时，先按症状查 [常见问题与已验证方法](references/solutions.md)，核对适用条件后复用思路，不从零重复试验。
- 当前角色确实使用 Rigify → Man 与 ARP 时，再读 [历史骨架配置](references/rigify-man-profile.md)。其骨名、开关数值和插件字段不是其他角色的默认值。

## 1. 读取并分析动画

通过所选 MCP 确认文件路径、Blender/插件版本、源和目标骨架、源 Action 与实际 Slot、帧范围、FPS、播放范围及目标当前 Action。记录 NLA、约束、驱动、对象变换、单位与 IK/FK 状态。

检查动作类型、真实运动来源、身体与四肢运动、接触阶段、循环接缝、整体位移和旋转。读取依赖图求值后的关节/结果骨；不凭控制器名称推断动画来源。源控制骨静止而结果骨运动时，映射入口须相应调整。

区分单位缩放归一化、角色尺寸匹配和参考姿态校准。先判断哪项确有需要；缩放可能涉及骨架、网格和动画，不能作为无条件预处理。

## 2. 检查并填写映射

识别实际重定向工具，检查本机 RNA/插件实现或可用接口后再使用其映射字段与操作。不要将所有工具当作 ARP。

输出并填写源骨 → 目标骨/控制器的对应，包括左右侧、躯干、颈头、四肢、脚趾、手指、骨盆/Root 入口、IK 链及 Pole。逐项核对实际骨名、父子链、运动职责和目标模式；标注缺失、歧义与不参与项。

检查失效 Source、Action、Slot，旧映射残留、重复写入目标、漏传骨盆位移及重复叠加旋转。映射名称有效只代表第一层检查通过，不代表动画适配完成。

同构新源先比较骨名、层级、静止矩阵、骨长和参考数据覆盖，再决定复用。不要只凭名称相同复用 Saved 参考姿态。完成后说明已填内容、未确定项和根运动方案，交给用户调整参考姿态。

## 3. 配合参考姿态与正式重定向

给出当前工具的参考姿态入口和有效控制器。检查源动画/NLA 是否覆盖编辑、IK/FK 是否与源动画烘焙模式一致、旧 Saved 是否实际启用。

由用户手动摆姿态并 Apply。不要自动重置用户正在编辑的参考姿态，也不要为了让 FK 控制器生效而直接切换有动画的 IK/FK 模式；可能需要先保姿吸附或整段转换。

正式重定向前核对来源、真实 Action/Slot、完整范围、参考姿态生效、目标模式及现有约束、原动作保留。提供当前工具的完整烘焙参数，等待用户点击完成。用户已完成时直接检查，不要求重复完整流程。

## 4. 检查重定向结果

在统一坐标、比例与约定根运动方案下比较源和目标求值姿态。先检查骨盆与躯干，再检查四肢关节、末端、膝肘弯曲平面、接地/接触和循环。不同骨轴之间不直接比较本地欧拉角。

检查完整相关帧范围；插值或接地可能越界时追加半帧或更细采样。脚底判断优先用求值脚部/鞋底网格和实际地面，不能用 IK 主控高度代替。

报告部位、帧段/最差帧、误差和单位，区分确认原因与假设。轻重依据可见程度、持续范围、角色比例、接触破坏及修复复杂度判断，不把历史厘米/角度当通用阈值。区分建议用户手修的局部问题和建议自动处理的系统问题。

## 5. 修复、验证与交付

1. 读取最新基线，记录 Action/Slot、NLA、帧/子帧、相关属性、约束和曲线；需要时记录原曲线摘要，验证未授权部分保持原样。
2. 从当前目标 Action 复制测试 Action，按症状读已有解法。优先处理上游问题：动作/模式、参考姿态及骨盆位置、足部原点，再处理 Pole、接触和局部曲线。原因未验证时不要连续重烘焙正式结果。
3. 在副本测试最小必要范围，保留用户有意的位移、旋转、手调和绑定结构。不把修改 Pole Angle、骨轴、约束或全身抬高当通用修复。必须扩大范围时解释原因并确认新增范围。
4. 复查完整动作及必要子帧，验证源 Action、原目标 Action、约定不改的曲线与根运动；检查新跳变、拉伸、滑步和接触破坏。连续试验无改善或依赖未确定条件时停止写入，保留基线并说明阻碍。
5. 测试通过后确认实时基线未被用户改变，将修复 Action 提交到原文件的目标骨架。核对兼容 Slot 和通道绑定，设置新旧动作保留方式（通常 Fake User），不覆盖原 Action。切换动作复验，防止未关键帧的 IK/FK 等属性残留。
6. 让用户能直接播放新 Action，恢复不影响结果的临时环境状态，只清理本次明确创建且无用途的临时数据。磁盘保存遵循用户已有指示；未要求保存时说明结果在当前场景、尚未写盘，不自动另存 .blend。

交付说明原/新 Action 名、改动范围、验证范围和残余问题。未经检查的部分不称为通过；隔离测试不称为已应用当前场景。

## 积累可复用解法

按用户要求，将已验证的新方法补充到 `references/solutions.md`：症状、确认依据、适用条件、思路、无效尝试和验收。通用方法与骨架专用参数分开，案例参数进入骨架参考，不升级为全局规则；证据不足的结论标为假设。

重复逻辑明确、适合参数化且能独立验证时才新增脚本。不要直接收录含硬编码路径、帧数、骨名、顶点索引或破坏性保存行为的历史脚本。全局 skill 不可写时保留工作区更新稿并说明待同步位置，不声称安装版已更新。
