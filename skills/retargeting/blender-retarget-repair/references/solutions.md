# 常见问题与已验证方法

先按症状选择条目，核对证据和适用条件，再在当前基线的独立 Action 测试。历史原因不是新问题的默认诊断。

## 1. 换动画后骨名有效，却烘焙错动作或范围

**证据**：Source 指向旧对象；工具记录的 Action 已不存在；活动 Action 与 Source Action 不同；多槽取到形态键槽；播放范围截断完整 Action。

**方法**：读取真实源 Action 和兼容 Slot，刷新工具来源及完整范围。只在结构改变或映射失效时重建列表；同构不同 Action 可以复用映射，但要检查参考姿态在新对象是否启用。

**验证**：抽查具有明显动作特征的帧，确认本次来源，完整范围被覆盖。骨名有效不能替代动作检查。

## 2. 四肢有动，骨盆重心却丢失

**证据**：映射的源躯干控制器静止，而实际骨盆结果骨移动；源/目标真实髋中心轨迹明显不符。

**方法**：找到承载骨盆位移的骨，设置正确的位置入口；必要时将位移与骨盆旋转分给不同目标控制器，避免重复写入和旋转叠加。

**历史实例**：某 UE2rigify 动作的 `torso` 静止，`tweak_spine` 跟随骨盆；改用 `tweak_spine → Torso` 传位移，保留 `ORG-spine → Hips_FK` 传旋转后恢复重心。此骨名不适用于所有 Rigify。

**验证**：真实髋中心恢复自然重心，躯干与上臂朝向未重复叠加。

## 3. 参考姿态编辑无反应，或 Saved 不生效

**证据**：Action 已解除但 NLA 仍启用且使用 Hold 等外推；调整了被约束的结果骨；调 FK 控制器时该肢体实际在 IK；旧 Saved 不匹配或 Preserve 未启用。

**方法**：记录配置，正确退出当前编辑后处理干扰的源 NLA，再重新进入参考编辑；让用户调整真正有效的控制器。复用 Saved 前核对静止方向、骨长、层级、覆盖范围及实际启用状态。

**边界**：同名不等于相同姿态；不能为了方便摆姿态随便切换有动画的 IK/FK，必要时先保姿转换。

**验证**：控制器能驱动对应结果；用户 Apply 后参考数据生效；退出参考编辑恢复正确源动画。

## 4. 参考偏移异常且左右不一致

**证据**：完整恢复参考姿态后的脚踝位置，与工具恢复部分控制器时记录的位置不同，动画偏移接近固定量。

**方法**：分开“设置全部参考控制器”和“求值、读取结果骨”：先恢复全部参考变换和必要模式，再统一更新依赖图，最后采集结果。不要逐骨恢复时过早读取受上游约束影响的脚部矩阵。

**条件**：历史 ARP 环境曾复现；当前版本应再次证明读取顺序导致误差。优先在隔离试验或本次前后处理解决，不默认修改安装插件源码。

**验证**：参考求值可重复；左右差异由真实姿态解释；重新测试后误差下降。它可能只解决部分偏移，仍需核对主控原点。

## 5. 站立误差小，脚旋转后大幅穿地/错位

**证据**：源脚原点位于脚踝，目标主控位于脚底/前脚掌；主控旋转接近，但真实踝与鞋底仍错位，偏移随姿态变化。

**方法**：在对齐的参考姿态建立源踝/目标踝关系，保留需要保留的足部旋转，以真实目标踝误差反求 IK 主控位置。考虑对象矩阵、父级、约束空间与旋转后的原点偏移，不只添加固定高度。

直接写矩阵不稳定时，可在副本微扰主控位置，更新依赖图并测实际踝响应，建立局部雅可比迭代求解。检查奇异性、步长和收敛并设置停止条件；不可达或近伸直情况要报告，不能无限迭代。

**接地**：求值脚部/鞋底网格，对实际地面测距。结合源支撑/抬脚时序保留腾空高度，先核对源本身有无穿地。修正应平滑进入/离开接触，不把整段脚底压在地上。

**验证**：踝轨迹、鞋底最低点、支撑滑移、抬脚时机和帧间插值。历史约 5 毫米间隙只适合当时基线，不是通用标准。

**不足的办法**：整体抬高会影响身体及另一只脚；只改 Pole 不能修脚踝与主控原点；主控 Z 不能证明鞋底不穿地。

## 6. 膝盖翻转或坐姿内扣

**证据**：求值髋、膝、踝建立的弯曲平面偏离源动作；先排除源/目标模式错误。Pole 左右位置不对称本身不是问题。

**方法**：先修骨盆与脚踝，再按源平面、目标链轴向及现有 Pole Angle 关系求 Pole 方向。近伸直时弯曲方向退化，延续邻近有效帧方向并处理时间连续性。

**边界**：Relative: Chain 和骨名正确不保证膝向正确；不默认改绑定 Pole Angle，不以左右 Pole 镜像为目标。

**验证**：全段平面连续、无反折跳变，脚踝及接地没有被破坏。

## 7. 坐姿整体偏差，手掌悬离大腿

**证据**：方向接近但真实髋中心位置偏离；两套骨盆主控不在同一解剖点。相同手臂角度因体型差异仍会失去接触。

**方法**：用真实髋中心校准骨盆，保留落座下降、后移与躯干倾斜，再修足部/膝盖；最后依据大腿或椅子的实际锚点处理手掌位置和朝向，平滑进出接触阶段。

**边界**：相同欧拉角不会自动恢复接触；不可达时报告需要的躯干/接触取舍，不无限拉长四肢。没有椅子几何不能声称椅面接触已验证。

**验证**：落座过渡、髋位置、脚底、膝向、掌距和形变，根运动保持约定。

## 8. 停掉 Torso 前进后，身体与脚拉开

**证据**：整体位移分散在躯干、脚 IK 和 Pole 曲线，静音一个通道后其他控制器仍继续前进。

**方法**：先确认归并根运动还是原地化；识别实际根轨迹和全部受影响控制器，检查父级/约束是否跟随指定根。将整体运动写根，同时从其他轨迹扣除同一运动，保留局部摆动、起伏及落座。

父级和骨轴不同，同一世界位移对应不同本地轴，必须转换空间。历史 Walk 可提取线性 Y 趋势，新动作须读取真实根曲线，不把所有轨迹强制首尾线性化。旋转涉及完整变换组合/逆变换，不能直接减欧拉角。

**验证**：转移前后全部相关求值骨/网格保持一致；原地化只去掉约定整体运动，身体与脚相对姿态不变。目标根通道为零不等于动画已原地化。

**状态陷阱**：静音曲线可能残留最后属性值；切动作也不一定归零。显式设置验证状态，原地 Action 用明确常量曲线或可复现状态。

## 9. 单帧编辑意外影响全段，基线变化

**证据**：Animation Auto Offset 等增量模式开启；单帧修改把整段曲线按增量移动。

**方法**：辨明用户有意手调与干扰，保留有意增量作最新基线。自动逐帧修复前记录并关闭传播模式，交付说明变化，不能悄悄恢复会继续污染修曲线的功能。

**验证**：只允许的通道改变；原 Action 及其他曲线的值、手柄、插值、静音和修饰器保持。

## 10. 修改 Bone Roll 后旧动作扭曲

**条件**：有可靠的修改前骨架参考，骨名、层级、head/tail 相同，主要差别是静止局部基。骨长、层级/约束也变时不能直接套简化方法。

**方法**：副本重建旧参考，保留当前其他绑定修改，以新旧静止基转换局部动画。纯基变换可用共轭变换作候选；父级继承、World Copy Rotation、IK 或混合约束必须额外求值验证、补偿残余。

保持四元数符号连续。比较 `pose_matrix @ inverse(rest_matrix)` 或求值网格形变，而不是要求新旧 pose 矩阵数值相同。

**边界**：缺旧参考时不能精确还原；不凭截图猜原 Roll，不默认重做绑定或改 Pole Angle。

## 11. Scale 为 0.01，改为 1 后切帧又恢复

**证据**：对象缩放被曲线驱动、单位不一致。先区分固定均匀、非均匀/动态缩放与父级影响。

**方法**：固定均匀缩放且工具确有要求时，在副本同步转换骨架静止数据、网格和位移动画，处理对象缩放曲线，保留旋转及有意骨骼缩放。位移值与曲线手柄一起转换。共享数据、形态键、约束距离和父级要额外检查。

**边界**：只改 Scale 或直接 Ctrl+A 不保证保留动画；这不是角色身高 Auto Scale，也不是每次必须执行的步骤。

**验证**：完整动作世界空间关节/网格、尺寸与轨迹前后一致，不只看一帧。

## 12. IK/FK 整段保姿转换

**方法**：先缓存全部原动作求值姿态，再逐帧吸附、切模式和写独立 Action。不能简单循环单帧按钮，使已修改的模式/曲线污染后续缓存。优先用该 rig 已验证吸附函数，核对按钮与真实方向。

**验证**：求值关节/网格、末端、脚趾和接触保持，切回原 Action 模式恢复。链长/伸缩差异导致不可精确保姿时报告限制；已烘焙不代表通过。新增 UI 按钮需另行明确开发请求。

## 新增条目

记录症状 → 证据 → 条件 → 方法 → 无效尝试 → 验证。场景骨名、帧数、地面间隙和角度阈值留在骨架配置或本次报告。证据不足标为假设，不将一次成功推广成通用结论。
