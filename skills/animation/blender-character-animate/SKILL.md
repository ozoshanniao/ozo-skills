# 制作角色动画

默认自然可信，先完成一版可播放动画，再与用户讨论修改。支持不同已绑定人形角色，通过职责映射适配实际绑定；其他形体需确认适配方法，不声称所有骨架已验证。

## 写入前的必要条件

发现当前 MCP 的实时场景、代码执行和图像能力，核对实例、文件、场景与目标角色。多实例未选定时先让用户选。MCP 不可用则说明阻碍，不悄悄改旧磁盘文件。没有图像能力时不能声称已做视觉检查。

**身体位移或旋转必须先询问分配方案并得到答复，再执行相关修改。** 分别明确：
- 平移写入对象、ROOT/次根还是身体主控，哪些轴，原地还是保留位移；
- 旋转写入哪里、哪些轴，如何处理朝向和前后动作衔接。

该问题来自用户明确规则。不得从现有动画、教程或游戏/镜头用途自行推断答复。明确覆盖当前动作的已有答复可沿用；范围/方案改变须重新询问。等待时可只读分析和规划，不因未答复开始依赖该决定的全身动画。

确认起止状态、范围/FPS、动作目的、接触目标及循环/镜头要求；非关键细节可采用说明过的合理假设。用户没有现成转身或接触动画，不要求补交才开始创作。

## 理解与保护当前状态

按 [MCP 执行与动画数据](references/execution.md)记录最新基线，确认角色职责映射、实际 IK/FK 与空间，不能只凭有关键帧判断控制权。保留用户烘焙的 FK/IK 曲线，不擅自清理。

新动作建立独立 Action；修改时保留原版，在副本完成。绑定正确兼容 Slot，不把同一 Action 内新增 Slot 当作新动作。保留原 Action 和用户最新手调；普通动画不更改静止骨、骨轴、层级或网格绑定。

## 制作首版

1. 将目标拆成关键姿态、节奏、过渡、接触事件和风格选择。按当前用途处理根运动、支撑及方向；不强制逐帧全控制器打键。
2. 在正确模式和空间操作控制器或绑定提供的属性，完成主要动作，再增加肩髋配合、手指、头/视线和跟随。角色尺度按身体比例适配。
3. 对自由运动、接触和模式切换选择合适 IK/FK；切换必须使用已验证的保姿方法，检查切换帧与中间帧。不能直接改开关造成跳变。
4. 接触、持物、代理物及辅助约束按 [接触与空间切换](references/contact-and-space.md)处理。用户允许按需创建辅助空物体、临时约束、代理道具和烘焙；使用已有资源优先，不重复询问这项总许可。
5. 衔接比较起止姿态、速度、根方向、接触、模式/空间状态；转身处理换重心和脚部转轴，站起不默认倒放坐下。必要时重做过渡段，不能只拼姿态。
6. 自主检查多个角度、完整相关范围及需要的子帧，修正明显问题后交付可播放首版。不是每一阶段都等待人工审阅；根运动问题例外，必须先得到答复。

脚控高度不等于脚底高度，骨盆关节不等于臀部表面。以实际网格与目标表面验证接触；无地面几何时只能按明确假定的平面诊断，不宣称通过真实接地验收。

## 检查与交付

游戏用途检查根运动契约、循环/衔接、支撑、曲线及需要的导出行为；镜头用途检查相机可读性、注意对象、动作重点、时长和道具关系。没有要求导出或发布时不自动执行。用户同时需要两类用途，不代表每次必须生成两份动作。

检查曲线覆盖、约束求值、突然翻转、肢体拉伸、膝肘跳变、接触和实际变形；首尾姿态相同不能代替速度/角速度及接触连续性检查。没有台词或音频依据时不宣称语音同步。

失败时保留原基线，说明失败部位、帧段和原因证据；原因不明、连续试验无改善或用户更改了基线时停止重复提交，先诊断/合并最新状态。

交付原/新 Action、实际 Slot、范围/FPS、根运动方案、模式/辅助依赖、检查范围和残余问题，让用户能直接播放。原动作防止意外丢失；辅助数据仅清理本次创建且已无用途的部分。未要求保存 .blend 时不自动保存，并说明未写盘。安装 Skill 不授权修改当前场景。
