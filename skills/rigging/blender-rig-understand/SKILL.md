# 理解角色绑定

为后续创作建立“身体职责 → 实际控制器/属性”的档案。以已绑定人形角色为首版验证范围；非人形可分析，但需另行确定职责与动作方法，不声称已通用验证。

## 连接与基线

发现当前环境的 Blender MCP 工具及能力，使用可用的状态、场景读取和代码执行接口。工具名、端口和 Python 路径不是固定契约。多个可用实例且用户未选定时，列出文件/实例让用户选择；核对实时文件路径、场景和目标对象，不默认用前台或最近文件。

记录 Blender 版本、单位、对象世界变换、网格、骨架数据、当前帧/子帧、模式、选择、Action/实际 Slot、动作与播放范围、FPS、NLA、约束和驱动。用户只要求分析时保持只读；临时切帧须在 finally 中恢复，不保存文件。MCP 不可用时明确实时分析受阻，不能用旧磁盘文件冒充当前状态。

## 识别实际职责

按需读 [角色档案字段](references/rig-profile.md)，识别：
- 总根、次根、身体主控、骨盆、脊柱/胸、颈头及视线；
- 左右肩、上臂、前臂、手、手指，腿、膝、脚、脚趾和 Pole；
- IK/FK、跟随、父空间、脚掌滚动、伸缩、保姿吸附的属性或接口。

骨名、骨集合、形状、锁定通道和父级只是线索。追踪驱动、约束目标/顺序、影响值及机制骨至求值结果骨，再确定控制权。验证相关动作范围内开关是否变化，不用当前一帧替代全段模式判断。FK 与 IK 曲线同时存在可以是用户有意烘焙以方便编辑；不能自动清理另一组曲线。

区分世界、对象、姿态、父级和控制器局部空间，记录旋转模式、静止基、有效轴、缩放及继承方式。不要把本地欧拉角相同当作跨角色姿态相同，也不要凭属性名猜 0/1 含义。辅助空间骨存在不代表控制器实际使用它，须追踪真实父级和约束。

读取自定义属性的 UI 范围、驱动表达式或绑定实现；未验证的切换/吸附方法标记未验证。分析请求不授权切换开关、扰动控制器或创建结构测试。用户要求制作/测试后，可在隔离副本上做最小探测，保证数据和约束/驱动目标也正确隔离，再验证原角色未被改变。

## 复用与交付

档案记录来源、验证时间/动作、骨架结构特征及限制。换角色时比较名称、层级、静止矩阵、长度/比例、约束、驱动和自定义属性；不凭骨数相同或名称相近套用。不把某角色的 Torso/Troso 拼写、IK/FK 值或参考姿态升级为通用默认。

交付可操作的职责映射、模式/空间含义、可用通道、已验证方法、疑点和下一步所需信息。优先检查最终网格而非只看骨架。

涉及身体位移或旋转的制作/修改前，必须先询问各自写入的对象/根骨/身体控制器、轴与根运动方案并等待用户答复。现有分配只是观察，不是对新动作的授权；已有答复只在明确适用范围内沿用。此规则不阻止用户授权的只读分析。
